# 时光小屋 V6 · 双人日常版

正式网址：https://love-cabin.onrender.com/

## 本次整体升级

- 重做首页与手机底部导航：今天、回忆相册、悄悄话、心愿清单、两人食堂、小屋设置。
- 相伴天数、原倒计时和公告沿用现有云配置；新增共享心情、纪念日及年重复纪念提醒。纪念日按北京时间显示，日历运算使用纯日期，避免时区偏差。
- 整合原有留言、日记、拍立得、菜单、订单、心愿和决策数据。八类原记录均不迁移、不重置，旧版首页保留在 `/classic.html`，登录后可继续访问历史功能。
- 新照片在浏览器压缩到最长边 1400px、JPEG 质量 0.8，单张原图最大 15MB，编码结果上限约 2MB，然后通过原相册接口保存。失败时显示错误，不先制造本地成功状态。
- 新版心愿操作由 PostgreSQL 行锁事务修改单条，保留原来的其他心愿和字段，避免双方勾选时覆盖整份清单。旧版整表接口保留以兼容历史页面。
- 日记、便签、点餐状态、图片大图预览、约会灵感及完整 JSON 备份导出均可使用。备份含原八类数据及新心情/纪念日，不含登录会话或口令哈希。
- 新首页不加载 Three.js、粒子动画、外部图标库或每天答错就锁一天的门禁。旧版的相关体验保留在旧版入口。移动端支持安全区域、暗色主题和减少动画偏好。

## 私密登录

双方使用独立的小屋共享口令。初始登录资料已单独交付到本机，不在仓库中；进入设置可修改，修改后双方所有旧登录失效。
`CABIN_PASSWORD_HASH` 是初始密码的随机盐 scrypt 哈希，仅存在本机 .env 与 Render 环境变量中。改密后以数据库私有文档为准。会话使用 HttpOnly、SameSite=Strict Cookie，生产启用 Secure；服务器仅保存令牌哈希，有效期 30 天，退出后撤销当前会话。
所有原业务 API、照片、音频和旧页面在生产中均需要登录，`/ping`、新首页外壳和必要静态代码可公开加载。写请求验证来源，登录限制每个连接地址 15 分钟 30 次。公共 API 不再允许任意跨站读取。受保护静态资源使用 private/no-store；新版 Service Worker 不缓存 API 或私密媒体，退出时清理旧资产缓存。
新首页设置内容安全策略与防嵌入响应头；所有用户文字按纯文本展示，不插入可执行 HTML。
本地未配置口令且不在 Render 时允许开发预览，不应将该模式用于公网。Render 缺少口令时业务数据保持锁定。

## 数据和运行

沿用原 Neon 项目、Render Free 服务、数据库凭据与 `/ping`。没有增加收费资源或外部 API。
新增数据以独立 id/kind 文档存放在已有 config 集合中：`v2_mood:*`、`v2_event:*`、`v2_session:*`、`private_cabin_auth`，与原 `global` 配置隔离；原配置接口不会返回这些私有文档。没有数据库表结构变更，也不执行历史数据回灌。
本地运行：Node 24，npm ci，npm start。真实 .env 不提交 Git。没有外部数据库时，仅新功能开发状态保存在忽略的 .private/ 中；线上数据库故障不降级为临时文件。
活跃且可见页面每分钟同步，隐藏或空闲超过 3 分钟后暂停；点击顶部重试按钮或返回页面恢复同步。

# Love Cabin 数据库部署说明

网站：https://love-cabin.onrender.com/

本次为既有网站接入独立的 Neon PostgreSQL 项目 love-cabin，继续使用 Render Free Web Service 和原网址。

## 数据范围

留言及拖拽坐标、全局配置、心愿单、日记、决策记录、拍立得、菜单和订单全部保存在数据库中。现有接口和前端数据格式保持兼容。

旧线上数据通过 API 加密备份后一次性导入。迁移标记确保重启或重新部署不会重复导入、恢复已删除的旧记录。数据库连接失败时返回错误，PostgreSQL 模式不会降级写入 Render 临时 JSON 文件。

## 本地运行

需要 Node.js 24，运行 npm ci，然后 npm start。
在本地 .env 中设置 DATABASE_URL，连接字符串需保留 TLS 参数。未设置数据库连接时，本地开发继续使用原 JSON 文件；Render 上缺少云数据库配置则拒绝启动。
现有 MONGODB_URI 支持保留；同时设置 DATABASE_URL 时优先使用 PostgreSQL。

使用 pg 连接池；遇到 Neon 原生 TCP 网络中断时，可通过官方驱动以加密 WebSocket 连接同一数据库，仍支持事务，不会切换到临时存储。

## Render

- 服务：love-cabin，原有 Free 计划
- 分支：main
- 构建：npm ci --omit=dev
- 启动：node server.js（DATABASE_URL 通过 Render 环境变量提供）
- Node：24，由 .node-version 指定
- 轻量健康检查：/ping
- 数据库状态：/api/storage/health

密码只保存在 Render 环境变量和本机忽略的 .env，未提交到 GitHub。

## 验证和迁移

npm test 执行静态文件访问限制、PostgreSQL 集合读写、数据类型、排序、并发字段更新、迁移幂等和数据库故障不落本地等测试。

一次性迁移脚本：node --env-file=.env scripts/migrate-postgres.cjs，从标准输入读取受控快照。必须包含 messages、config、wishlist、diary、decisions、polaroids、food_menu、food_orders 八个数据分组。脚本只在迁移标记不存在时导入，不覆盖已有记录。

切勿删除数据库或 cabin_migrations 表来“修复”连接问题。重要数据请定期导出独立备份。浏览器中仅用于界面偏好的本地设置不在这八组服务端数据之外另行同步。
